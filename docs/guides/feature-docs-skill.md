# 功能文档 Skill

`skills/feature-docs/SKILL.md` 是功能代码地图维护流程的权威源。它帮助修改代码的人找到
实际入口、执行链、关键契约、修改影响和对应验证，不替代开发规范、架构设计或用户指南。

## 使用

可向 Agent 请求：

- “用 feature-docs 整理认证功能，重点说明两域隔离与会话入口。”
- “根据当前 diff，同步受影响的功能文档和指南。”
- “检查这篇功能文档是否把遗留实现写成了当前主路径。”

默认沿用当前文档组织，局部任务只修相关页面。引入新的功能文档体系时，先建立一个真实
示例与最小索引，不预建空领域。开发规范（例如前端视觉与交互约定）应维护在规范目录。

## 输出与维护

文档需要解释一次实际调用如何从入口走到结果；关键事实定位到文件及符号，明确源码事实、
推断和未确认行为。“要改什么 → 去哪里 → 影响什么 → 如何验证”应能回答具体修改问题。
同步时从变更符号、契约和旧路径寻找影响，修正相关入口、指南与索引。

文档构建通过只证明站点可构建，不代表功能测试通过。交付说明记录实际检查与未验证范围。
示例参见仓库的 `skills/feature-docs/references/feature-map-example.md`。

## 效果评估

评分方法与三个任务定义位于 `skills/feature-docs/evals/`。评估使用新旧版本独立上下文和相同
输入，保留源码快照版本、受控变更、原始输出及盲评结果。三任务平均至少 90、单项至少 85、
无关键事实错误及虚报验证，并通过独立读者定位检查，才算本轮达到 90 分。

样本表现不能外推为跨仓库成功率；耗时增加和无法取得的 token 用量应一并披露。
本轮证据位于 `tasks/evidence/feature-docs-20261023/`；目录中的报告记录最终分数及限制。
