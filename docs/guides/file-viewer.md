# 本机只读文件与改动查看器

`just view` 起一个只绑本机回环地址的只读界面：默认落在**改动视图**——左边按「已暂存 /
未暂存 / 未跟踪」三段列出有改动的文件，右边是逐行 diff，顶部可以一键切到文件树视图。它
代替「为了读一个文件或看一眼 diff 就开一个完整 IDE」这件事。文件视图里 Markdown 可以
按需预览、HTML 可以在新标签页里当真实文档打开，边界见下文「预览的边界」一节。

**它只能看。** 界面里没有编辑、暂存、提交或冲突解决，服务端也不存在任何写入路由——
只读是硬边界而不是「本期先做一半」。需要改代码请用你惯用的编辑器。

## 命令面

| 命令 | 作用 |
|---|---|
| `just view` | 起（或复用）本仓库的查看器，并在浏览器里打开，默认进改动视图 |
| `just view <路径>` | 打开后直达某个改动文件；路径是相对仓库的路径 |
| `just view --files` | 进文件视图而不是改动视图，显示完整文件树 |
| `just view --diff` | 显式进改动视图（与 `just view` 等价，保留为显式写法） |
| `just diff` | `just view --diff` 的薄别名，无独立实现 |
| `just view --stop` | 立刻回收本仓库的常驻实例 |
| `just view --port <端口>` | 指定监听端口（优先级：显式 `--port` → 登记里的值 → 默认 8791 → 系统空闲端口） |
| `just view --idle-timeout <秒>` | 空闲回收时限，`0` 表示关闭自动回收 |
| `just view --no-reuse` | 强制新起一个实例，不复用既有实例。旧实例不会自动收掉，需要时用 `just view --stop`，或等它自己闲置回收 |
| `just view --no-open` | 只打印 URL，不打开浏览器 |

`--diff` 与 `--files` 互斥。改动视图是默认视图，因此 `just view --diff` 与 `just view`
等价；`--files` 是回到文件树的唯一入口。

改动视图永远三段全列，没有「只看某一段」的开关，也没有比较基线可选：比较对象固定是当前
工作区，用 `git status` 的三段口径切开。

每个 worktree 各自独立：登记文件与端口按 worktree 分开，多个 worktree 或派生项目并存
时互不干扰。派生项目 `just sync-template` 之后同样获得这条命令，不需要本地分叉。

## 界面用法

- **改动视图**（默认）：左树分三段——**已暂存 / 未暂存 / 未跟踪**——每段一条标题行（带
  该段文件数），段内再按目录分组。目录行可折叠并显示其下的改动文件数，叶子行显示状态
  徽标与 `+N -M`；点开任一文件看逐行 diff（旧行号与新行号并列，增行绿底、删行红底）。
  两个视图共用同一套目录树，只是叶子行不同。
- **三段的来源**：已暂存取 `git diff --cached`（HEAD ↔ 索引），未暂存取 `git diff`
  （索引 ↔ 工作区），未跟踪取 `git ls-files --others --exclude-standard` 列文件，点开
  某个文件时才用 `git diff --no-index -- /dev/null <文件>` 求它的逐行 diff。界面上的
  文件集合与增删统计与这些命令的终端输出逐项一致，不做二次推断。
- **未跟踪那一段不显示 `+N -M`**：`git` 的列表类命令都不为未跟踪文件报这个数，唯一能拿到
  它的口径是逐个文件跑一次 `--no-index --numstat`。本机实测每个文件约 8ms，800 个未跟踪
  文件要 7 秒左右（并发跑到 8 路也只降到 4 秒，瓶颈在进程创建），页面会像卡死。因此这一段
  只列文件、统计列留空——**不编数字**，也不把「本轮没取」显示成「二进制」。逐行 diff 照旧
  可看，那一次调用是点击时才发的。
- **同一个文件可以同时出现在两段里**：暂存之后又改的那几行属于未暂存。条目的身份因此是
  「路径 + 分区」，两段各自的 diff 内容不同。`just view <路径>` 直达时按分区顺序（已暂存
  优先）取第一个匹配的段落。
- **未跟踪一段沿用文件树的目录剪枝**：派生项目忘了把依赖目录写进 `.gitignore` 时，整棵
  依赖树既不该进文件树，也不该淹没改动列表。两处是同一份口径。
- **文件视图**：点顶部「文件」切过去，左侧是完整文件树，点目录折叠展开，点文件在右侧
  看带行号与语法高亮的正文。顶部过滤框按路径筛选（两个视图都适用），命中的路径其祖先
  目录会自动展开。
- **预览**：默认永远是源码。打开 `.md` 时头部多一个「源码 / 预览」开关，点「预览」才向
  服务端要一次渲染结果，取回后缓存在内存里，来回切换不再重复请求；换文件或切视图后回到
  源码。打开 `.html` 时头部给的是「在新标签页打开」——查看器不内联渲染 HTML，而是把文件
  原样供出，让浏览器在自己的标签页里当一个真实文档打开，页面里的相对引用（`./a.css`、
  `../img/i.png`）能按原路径解析回来。两种控件都只在当前文件支持时出现，其他文件的头部
  只有路径与复制按钮。
- **重命名**：状态徽标为 `R`（蓝色），点开后按「旧路径 → 新路径」配对给出逐行改动。
  内容没变的纯重命名会明说「重命名，内容未变」——路径确实变了，不能报成「没有改动」；
  内容也改了的，头部会标注重命名自何处并照常给 hunk。
- **二进制与超大文件**：超过 256 KiB 的文件与二进制文件给出明确说明而不是渲染正文。
  改动视图里二进制的改动会标成「二进制文件，无逐行改动」——它确实变了，只是 git 不逐行
  给，不能报成「没有改动」。
- **复制路径**：内容区头部路径右侧有一个复制按钮，点一下把该文件的仓库相对路径写进
  系统剪贴板，图标短暂变为对勾作为反馈。头部没有真实路径时（未选中文件、提示块、服务
  已退出）按钮自动收起。
- **两个视图各记一份「上一次看的那一个」**：在改动里看到一半切去翻文件、再切回来，仍停在
  原来那条改动上（分区一起还原，同一个文件的两段不会串）；反过来也一样。只有**成功读到内容**
  才被记住，读失败的提示块不会占住这个位置，否则每次切回来都会重弹同一个错误。还原是尽力
  而为：文件被删了就照实说「未找到文件」，改动被提交了就让改动视图回到空态。
- **从改动跳到文件**：改动视图里选中任一改动文件后，头部路径右侧出现「查看文件」，点一下切到
  文件视图并选中同一路径的完整正文（祖先目录会自动展开，选中态在树上可见）。这一步是显式指定，
  **优先于**上面那条记忆——它要的是「看你点的这一条改动对应的文件」，不是「回到上次看的文件」。
  文件视图里不显示这个按钮——那里本来就在看正文。改动里已被删除的文件跳到文件视图会得到明确的
  「未找到文件」：文件确实不在了，查看器不拿索引里的旧内容冒充它。
- 快捷键：`d` 切改动视图、`f` 切文件视图、`/` 聚焦过滤框。

## 预览的边界

预览默认关闭，只有两种文件有预览入口。判定**只看后缀，不做内容嗅探**——与语法高亮同一
口径：让「这个文件预览成什么」随正文漂移，排障时无从解释。

| 文件 | 头部给的入口 | 走哪条路 |
|---|---|---|
| `.md` / `.markdown` | 「源码 / 预览」开关 | 服务端渲染成 HTML 片段，按需取回后内联进内容区 |
| `.html` / `.htm` | 「在新标签页打开」 | 文件字节原样供出，由浏览器在新标签页里渲染 |
| 其他文件 | 无 | — |

几条明确的边界：

- **改动视图不预览**：那里对 `.md` / `.html` 仍是逐行 diff，头部也不会留下预览控件——从文件
  视图带着一个 `.md` 切过来时，「源码 / 预览」开关与「在新标签页打开」都随正文一起收掉。
- **渲染依赖缺失时预览入口不出现**，源码与语法高亮照旧。`markdown` 与 `pygments` 一样是
  显式声明的 dev 依赖；派生项目 `uv sync --no-dev` 之后查看器功能不缺失，只是没有预览。
- **超过 256 KiB 的 Markdown 不预览**，与正文渲染同一上限：预览侧再放一次，就等于绕开了
  大文件那条分支。
- **Markdown 里的 raw HTML 会被执行**，正文里的相对图片也不会解析（预览片段在查看器页面
  里，不在文件所在目录，图片会加载失败）。查看器绑在本机回环上、只读，预览又是用户主动
  点开的一次；这里刻意不做清洗——清洗过的结果已经不是文件本身，那比不预览更容易误导。
- **HTML 走原样供出的路由**（`/raw/<仓库相对路径>`），并且保持路径原样，这是相对引用能
  生效的前提。它仍然逐字经过与其它读取接口同一份越界断言（解析成绝对路径后必须仍在仓库
  根之下），目录、缺失与越界分别给出明确拒绝。
- **在新标签页里打开的页面与查看器同源**：那个静态文件里的脚本因此可以调用查看器的只读
  接口。查看器只读、只绑回环，被打开的又本来就是仓库里的文件，这一点按接受处理而不是靠
  沙箱隔离——真要隔离，代价是相对资源全部加载不到。

## 与 `git status` 的差异

改动视图按需向 `git` 取数据，不调用 `git status`，因此有两点值得知道：

- **未跟踪**这一段的集合来自 `git ls-files --others --exclude-standard`，与 `git status`
  里 ``??`` 的口径一致；但被上述目录剪枝挡掉的路径不会出现。
- **被忽略的文件**（``!!``）在所有接口里都不出现，与文件树一致。

## 常驻与回收

查看器是一个常驻本机进程，「第二次打开是秒开」正是它换来的：命中的第二次调用只开一个
新标签页，不重启进程。

常驻进程必须同时具备两条回收路径，这是本仓库不接受「常驻但没人管」的直接结果——见
`docs/ai-standards/tooling.md` 里那条「手敲的三次 `just test` 在 14 小时后仍常驻内存」
的教训。

- **自动回收**：服务按「最后一次请求时间」计时，默认 **30 分钟**没有任何请求就退出并
  清理登记。时限可用 `--idle-timeout` 调整，`0` 表示关闭自动回收。
- **显式回收**：`just view --stop` 读登记 → 给服务进程发终止信号 → 清理登记。结束实例
  刻意走进程信号而不是 HTTP 接口：只读是硬边界，不为运维便利开第一个写口子。

**页面不做心跳轮询**，所以「关掉标签页」就等于进入空闲，关掉后不必再管它。代价是页面
开着但长时间不碰也会被回收，此后页面会失效。服务退出后页面会切换到明确的「服务已退出」
提示并给出重新连接指引，而不是留一个半渲染的坏页面——重新执行 `just view` 即可。

## 性能承诺边界

承诺只覆盖**进程侧**，而且只承诺这两条：

| 路径 | 承诺 |
|---|---|
| 复用命中（第二次及以后的 `just view`） | 从敲命令到浏览器开始加载 ≤ 150ms |
| 冷启动（首次 `just view`） | 从敲命令到首个只读接口返回成功 ≤ 400ms |

**这两条余量对机器负载很敏感**：路径上只有一个 `just` 进程加一个 Python 解释器，两者
的成本几乎全是解释器启动与导入，而这部分在 CPU 被别的进程挤占时会被放大约一个数量级
（本机实测空载 `python -c pass` 约 9ms，负载 17 时约 50–100ms）。同一份代码在空载机器上
两条预算都有十倍余量，在超载机器上则可能双双超标。想判定它是否达标，请在机器不忙时
测，并在记录里带上当时的 load average——`rv5_measure.py` 会把它打在证据首行。

**浏览器冷启动不在承诺内**：本机实测浏览器未运行时冷启动要 1.5–3s。这是环境成本而不是
实现缺陷——查看器能把进程侧压到预算内，但没法让一个还没启动的浏览器提前加载。首次使用
时请把这 1.5–3s 算进去。

## 实例登记与排障

常驻实例登记在仓库根的 `.env.view-state`，与既有的 `.env.run-state` 同构：被 `.gitignore`
的 `.env*` 规则覆盖、不进版本库、每个 worktree 各自独立。

| 字段 | 含义 |
|---|---|
| `VIEW_PID` | 服务进程号，`--stop` 据此投递终止信号 |
| `VIEW_PORT` | 服务监听的本机回环端口 |
| `VIEW_REPO_ROOT` | 实例所服务的仓库根绝对路径，用于判定登记是否属于当前仓库 |
| `VIEW_STARTED_AT` | 启动时刻，仅供排障阅读 |

复用判定做三项交叉校验：**进程存活 + 端口可连 + 仓库路径一致**。三项缺一不可——单看
进程存活会撞上进程号复用，单看端口可连会撞上端口被别的进程占用，仓库一致这一项则让同一
台机器上的多个项目互不串台。任一校验失败即判定登记陈旧，清理后重新起服务，而不是打开
一个连不通的页面。

排障入口有三处：

1. `.env.view-state`：判断登记项是否陈旧、实例占的是哪个端口。
2. `logs/view-viewer.log`：服务的启动与回收日志（`logs/` 被 gitignore 覆盖）。
3. `just view --stop`：显式回收；登记项已陈旧时它只清理登记。

典型症状与处置：

| 症状 | 先查什么 |
|---|---|
| `just view` 每次都在重新起服务 | 登记文件是否被反复清掉；`logs/view-viewer.log` 里是否有空闲回收记录 |
| 页面提示「服务已退出」 | 正常回收路径。重新执行 `just view` 即可；想常驻不回收就 `--idle-timeout 0` |
| 端口被占用导致退让到随机端口 | 端口实际值只写在 `.env.view-state` 里，不在任何文档里硬编码，以登记为准 |

## 语法高亮的降级

高亮由 Pygments 在服务端渲染，`pygments` 在 `pyproject.toml` 的 dev 依赖组里显式声明。
依赖缺失时（例如派生项目做了 `uv sync --no-dev`）服务不会崩，只是降级为纯文本——行号、
文件树与改动视图都照常工作，功能不缺失，只是没有颜色。状态条会写明当前是哪种。

## 与改动报告技能的分工

`skills/git-diff-report/` 产出的是**可发送、可归档的单文件静态 HTML 报告**；查看器产出的
是**本机实时只读界面**。两者读者与生命周期不同：查看器不依赖、也不复制该技能的产物，报告
生成能力也不会被搬进查看器。

两个工具的**范围词汇**是对齐的，切换时不会看到两套口径：报告技能的 `staged` / `unstaged`
即查看器的「已暂存」/「未暂存」两段。差异在于报告技能还支持 `range --base <基线>`（整条
分支相对某条基线的改动）与 `head`（暂存 + 未暂存合并），而查看器只看当前工作区——要
「提交与提交之间比了什么」请用报告技能或 `git diff <基线>...HEAD`。
