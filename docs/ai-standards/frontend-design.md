# 前端设计规范

适用于 `frontend-public/` 与 `frontend-admin/` 的界面设计和实现。前端职责与边界见
[前端架构](../architecture/frontend-architecture.md)，验证证据要求见 [测试规范](testing.md)。

## 修改前先确认依据

先查看目标前端的主题变量、基础 UI 组件、布局与相邻页面，再决定本次界面的视觉和交互。
优先复用已有组件及其 variant；不要仅凭单张截图或个人偏好为同一语义另造一套样式。
两个前端可以有不同的视觉定位，不为统一外观引入跨项目源码依赖。

既有产品沿用其设计系统。尚无约定的新界面，先确定满足当前需求的最小颜色、字号、间距、
圆角和交互约定，并在项目规范中记录；不预先建立完整设计系统。
营销页面与高密度工作台可采用不同节奏，同类页面与同排控件保持一致。

## 视觉语义与复用

- 颜色、边框、背景和文字优先使用现有语义 token 与组件 variant；同一状态使用同一含义。
  不把某个业务的状态枚举、固定色系或尺寸写成所有派生项目的通用要求。
- 状态、异常和成败同时提供可读文案；颜色只能辅助识别。
- 字号、行高、圆角和间距沿用现有阶梯。同排按钮、徽章、链接重点核对高度与对齐，
  使用特殊小字号时显式确认行高及可读性，不以无限缩小文字解决拥挤。
- 对项目已支持的主题验证文字、背景、边框、悬停与焦点对比。使用语义 token 时依靠主题
  映射；直接指定颜色时补齐主题差异，无需给每个工具类机械添加 `dark:`。
- 图标复用已有库；装饰图标对辅助技术隐藏，纯图标操作提供可访问名称。

## 交互与状态

- 链接使用链接语义，操作使用按钮语义；不要嵌套链接与按钮等交互控件。
  整行可点击且有独立操作时，使用清晰的独立点击区域并保留键盘访问。
- 外链沿用项目的打开方式；支持修饰键与浏览器默认行为。新窗口链接配置合适的 `rel`；
  桌面宿主存在时复用已有外链适配，不在普通 Web 项目中默认增加桌面桥接。
- 复制操作不同时触发跳转，成功与失败有可感知反馈；反馈形式与时长沿用项目约定。
- 表单与异步界面按实际流程覆盖加载、空态、失败、禁用和成功反馈，避免重复提交。
- 修改支持中英文的界面时，检查受影响文案和状态在两种语言下的显示。中文界面可以保留英文；
  英文界面不得出现中文用户界面文案，除非当前需求明确要求该页面或状态使用中文演示。沿用
  现有翻译资源，不在组件中写死另一种语言的文案。
- 键盘可以进入、操作并离开交互区域；焦点可见。Dialog、菜单和浮层优先使用现有基础
  组件，保留焦点管理、关闭行为与 Portal 边界。
- 按产品目标端验证界面。同一功能同时面向手机与 PC，或分别实现移动端与桌面端页面时，
  至少检查手机竖屏和桌面横屏两个代表性视口中的溢出、文字截断与操作可达性；不要只把
  桌面布局压窄。表格确需横向滚动时，让滚动范围与关键操作清晰可见。

## 验证与项目定制

界面改动从真实应用入口观察默认态及受影响的关键状态。涉及同排尺寸或主题问题时，
用浏览器计算样式与 bounding box 辅助确认；不为所有界面强制做像素级断言。
截图标明验证层级，组件预览与交互原型不冒充生产流程验收，AI 生成图不作为实现证据。
无法进入真实流程时，说明已验证的范围和限制。

派生项目可在本页补充实际生效的颜色语义、尺寸、反馈与平台规则，并链接其组件实现。
新增约定只约束相应产品与场景；先更新规范，再让代码与之保持一致，不增加逐条强制校验器。
