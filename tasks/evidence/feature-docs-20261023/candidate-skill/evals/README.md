# 效果评估

在隔离源码快照上执行 `evals.json` 的三类任务，每个任务使用旧版和新版各一次，输入一致。
每个版本用独立上下文，执行者不读对方输出或评分 oracle；不能把评分规则预先灌入执行提示。
新增文档、行为变更同步、遗留文档修正均使用实际仓库代码，受控注入的变更应明确标注。
保存输入版本、完整原始输出、改动差异、实际检查结果与每次耗时。无法取得 token 用量时注明，
不以输出字数代替。源码快照与运行结果放 skill 目录之外，避免普通调用加载评估产物。

## 统一评分

| 维度 | 满分 | 判断 |
|---|---:|---|
| 定位与范围控制 | 20 | 完成任务并沿用现有结构，未扩大为无关代码或文档整理 |
| 源码调查 | 20 | 沿实际注册入口确认主路径、关键边界与相关测试 |
| 输出质量与可追溯性 | 20 | 关键事实正确、可追溯到符号，提供可执行的修改定位 |
| 增量维护 | 15 | 识别受影响引用、入口及导航，妥善处理陈旧和删除内容 |
| 效果验证 | 15 | 诚实记录实际检查，用修改问题验证可用性；不把待执行测试当通过 |
| 轻量与可迁移性 | 10 | 使用仓库已有工具、适当篇幅与结构，无不必要服务依赖 |

各维度按实际输出给分并引用证据，不按特定标题、关键词数量打分。比较每组同维度分数和耗时。
由没有参与产出者进行盲评，版本标签隐藏为 A/B。再用一名独立读者仅看新文档回答修改问题，
对照源码确认定位、影响、验证三项。发现严重错误应修正后换未见过的变体复测，不能修改评分
标准凑分；保留失败输出和修正记录。

达到 90 的约定：新版三任务平均至少 90，每任务至少 85，无关键事实错误、主路径误认或虚报
验证，并通过独立读者检查。样本小，只能说明本轮任务表现；不宣称跨仓库成功率或长期收益。
质量明显变好但更慢时披露代价；无改善也照实报告。没有真实输出时不授予效果分。
