# 功能文档维护

让修改代码的人能快速找到功能入口、关键实现、数据契约、测试和容易误判的地方。
先以源码确认当前行为，再更新对应文档；已有文档仅作为线索，不作为实现证据。

## 文档归属与权威关系

先读目标仓库的 Agent 入口与规范索引，遵循其语言、目录和文档同步要求。

- `docs/features/` 或仓库已有等价目录：具体功能的代码地图与修改提示。
- `docs/ai-standards/`：供 Agent 执行的开发规范。例如前端颜色语义、组件复用、主题和交互
  一致性应归 `frontend-design.md`；功能文档只链接规范，并记录该功能的实际组件与状态。
- `docs/architecture/`：跨模块边界、契约与设计理由。功能文档链接权威说明，不复制全文。
- `docs/guides/`：按仓库实际约定容纳用户或开发者操作指南，不假定只面向最终用户。
- PRD、设计记录与验收证据保留各自职责，不把历史实施流水账当作当前功能说明。

同一事实保留一个权威来源。不要因为用户提到了“文档”就创建功能目录；若请求实际属于
开发规范或指南，更新正确位置及入口即可。审查 skill 如存在可用于审查，但本 skill 不依赖它。

## 判断采用更新还是初始化

检查现有功能索引、模板、导航、Agent 阅读路由，以及待修改功能的文档。

- 已有约定：沿用目录和模板，补齐本次所需的缺失链接或页面。
- 只缺模板、Agent 路由或某层索引：局部补齐，不重建整个体系。
- 完全没有约定且用户要求引入功能文档：使用下方初始化流程。
- 本次只修一篇文档：完成局部修正，不默认扩成全库文档整理。

## 更新流程

### 1. 从实际入口追踪

用搜索与文件读取确认本次功能的：

- 目的、使用场景与当前主路径；区分生产入口、兼容层和遗留实现。
- HTTP 路由、CLI 命令、前端页面或后台任务入口，以及相应权限和前置条件。
- 沿仓库自身分层追踪的关键实现文件，每个文件说明职责。
- schema、持久化模型、配置项及其来源；不把配置变量名和实际密钥值混为一谈，不记录密钥。
- 对应测试、运行入口和验证条件；命令以当前任务入口、配置及测试文件为准。
- 源码能支持的常见坑：顺序约束、异常分支、兼容性、防御检查及容易被误读的边界。

不要为了凑“常见坑”把 TODO、猜测或未核实的旧行为写成事实。
列出文件前确认路径存在；CLI 旗标与配置名应核对定义或帮助输出。
范围较大时先沿关键路径调查，不遍历无关模块。

### 2. 写当前状态的代码地图

有模板就沿用；没有时按需求组织功能概述、入口、关键路径、契约、测试、常见坑与相关链接。
重点写修改时需要知道的内容，概述保持简短。无关栏目可省略；仓库模板要求保留时注明不适用。

复杂领域需要多篇文档时再引入领域目录和 `_index.md`，索引以“修改什么 → 阅读哪里”路由。
单篇小功能无需预建目录层级。不要填充空领域或指向不存在页面的占位链接。

前端功能记录页面、组件、状态及交互入口，链接已有设计规范；不在每篇功能文档重复设计 token。
新增规则若确属长期开发约定，更新规范源及相应阅读入口，而不是藏在功能说明里。

### 3. 补齐可发现性

更新现有功能索引与适用的领域索引；仓库有文档导航时同步登记。
Agent 入口指向功能总索引即可，不把每篇功能都复制进所有工具适配文件。
新增长期规范页时按目标仓库要求更新规范索引、Agent 路由与文档导航。
不另建第二套与现有索引竞争的清单。

### 4. 验证

- 核对本次新增或修改的源码路径、文档链接、命令和配置名；移动或删除路径时搜索旧引用。
- 执行仓库要求的一致性检查与文档构建，优先使用已有命令；确认没有本次引入的新警告。
- 文档列出的测试命令不等于本次已运行。报告实际执行结果；文档构建不证明产品行为。
- 若同时改动行为，遵循仓库测试规范，从最高可行保真度入口验证。截图区分真实用户流程、
  component preview 与 interactive prototype；AI 生成图不是实现证据。
- 检查差异和工作区范围；不主动暂存、提交或推送。无法完成的验证明确记录限制。

## 初始化流程

仅在用户要求采用功能文档约定且仓库没有等价体系时：

1. 确认现有文档组织、语言与 Agent 入口，选择兼容的目录。
2. 创建最小总索引与可复用模板；若采用 `docs/features/`，可使用 `index.md` 和 `_template.md`。
3. 选一个与当前请求相关的真实功能，完成源码调查和文档，作为可阅读示例。
4. 总索引只登记已存在的文档；其他领域按后续实际需求添加，不预建空页面。
5. 补齐 Agent 到总索引的阅读路由，以及适用的文档导航，执行上述验证。

## 同步时机

功能行为、入口、数据契约、配置或关键约束改变时，在同一改动中更新相应功能文档。
纯视觉约定变更优先更新前端设计规范；纯内部重构只修受影响的代码地图，不重写无关说明。
修复缺陷时，仅将有长期修改价值且源码可证明的边界沉淀为常见坑。
