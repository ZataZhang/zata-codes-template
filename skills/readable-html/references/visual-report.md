# 配方：图文汇报网页

适用于给领导或团队看的阶段汇报、项目成果介绍，以及“网页结合图片、原型和截图”的请求。普通复盘与调研仍按 `report.md`；本配方侧重成果说明和交付状态，不强制经过、根因或量化指标。

## 内容先于画面

先从用户材料提取每项工作的：已发生的变化、读者能理解的价值、当前交付状态、依据、下一步。技术记录转为业务语言，但不删掉影响结论的边界。

- 没有收益数据时写“预期价值”或“建设目标”，不编造节省时间、成本或完成比例。
- 方案、原型、实现、本地验证、人工验收、生产部署分别确认。测试通过不能直接写成上线完成。
- 保留用户指定的成果与图片。主页面简化表达，完整技术说明和验证记录放到可展开区域；不要把内容压缩为几个空泛图标。
- 不固定成果数、章节数、图数或页面长度。按材料组织，相关内容合并，无关内容不为填满模板而加入。

## 两层阅读

建议骨架，随内容调整：

1. **快速总览**：主题、截至日期、一段阶段结论、主要进展入口。
2. **成果展开**：每项成果讲变化与价值，配合适的解释图，再展示对应原型或实际截图。状态放在旁边的 HTML 文案里。
3. **其他进展与方案**：区分执行侧完成、待人工验收、方案储备。
4. **下一步**：具体行动和完成标准。有依据才填写负责人和日期。
5. **按需展开的材料**：完整技术路径、测试结果、PRD、验收边界与来源。

关键信息即使不展开详情也要可见，特别是影响主结论的风险、待修复问题和交付限制。

## 图片分工

| 图片 | 解决的问题 | 要保留的边界 |
|---|---|---|
| 生成的解释图 | 抽象能力如何工作，有什么用 | 标注示意图，不能充当交付证据 |
| 用户原型 | 计划中的页面与交互是什么样 | 标注设计原型及必要的历史版本信息 |
| 实际页面截图 | 页面已具备什么能力 | 标明实际验证环境，不推断生产部署 |

优先整理用户已有素材，保持截图比例、原始文字与数据。必要的局部放大应保留上下文或原图入口。历史演示不能用作近期变更已经交付的证明。每张图旁写清“看什么”和“它支持什么结论”。

解释图按需生成，使用当前环境可用的生图工具与相应 skill。没有生图工具时，复用素材或用可编辑图表说明，并如实说明生成限制。无需因为使用本配方就强制生图。

### 生图的边界

- 先确定这张图要说明的关系，随后选择风格和构图。一套页面保持配色、视觉语言与人物风格协调。
- 模型主要画能力示意和插图。准确的标题、状态、指标、说明文字用 HTML 排版，便于阅读和修改。
- 原型和截图用用户原始文件，不让生图模型重绘“证据”。
- 提示词包含受众、图要解释的关系、宽高比例、预留空间和禁止虚构事实等约束。没有必要时不加文字。
- 生成后检查关系与含义是否正确，保存实际提示词和图片素材到项目适当位置，不把项目数据带入 skill 示例。

## 页面组件

复用 `svg_kit.py` 的颜色令牌与外壳；`scripts/report_ui.py` 提供增量样式、内嵌图片、键盘可操作的图片放大、详情折叠和打印处理。它不强制某种章节布局，也不改变既有架构/流程图 API。

- 桌面端可用“左说明、右解释图”，随后排列截图。手机端改成单栏，不把桌面图和文字一起缩成小字。
- 长页面导航使用真实锚点。仅在长页确有帮助时固定导航，并为定位留出顶部空间。
- 大图使用原生按钮打开 `dialog`，支持 Enter、空格、Escape 和关闭后焦点返回。详情用原生 `details/summary`。
- 图表需横向滚动时，仅让图表容器滚动；页面主体不横向溢出。
- 打印时展开详情，隐藏导航和按钮，避免遮挡；打印结束恢复原折叠状态。
- 延续已有主题。辅助样式使用现有 CSS 令牌，截图以原始颜色显示。

### 最小集成示例

在临时生成脚本中导入，不把实例资料写进 skill：

```python
from html import escape
from pathlib import Path
from svg_kit import Section, page
from report_ui import evidence_figure, report_enhancements

# 本地文件会以 data URI 内嵌。kind 可用 diagram / prototype / screenshot。
figure = evidence_figure(
    Path('/absolute/path/screenshot.png'),
    title='费用明细页面',
    description='本地页面验证，尚未覆盖异常任务路径。',
    kind='screenshot',
)
content = (
    '<h2>费用追踪</h2><p class="lead">查看用量和调用时单价。</p>'
    '<div class="report-story"><div><h3>本期变化</h3>'
    '<p>功能已实现，异常场景完整性待修复。</p></div>' + figure + '</div>'
    '<details class="report-detail"><summary>完整验证记录</summary>'
    '<div class="report-detail-body">' + escape('在此填入有依据的验证记录。') + '</div></details>'
)
document = page(
    title='阶段工作汇报', eyebrow='阶段进展', h1='近期工作进展',
    thesis='先给阶段结论，再说明成果和下一步。',
    sections=[Section('cost', '费用追踪', content)],
    footer='截至日期、来源和验证限制由实际材料填写。',
)
# 一页仅注入一次。移除 page() 的在线字体依赖，使用系统字体，便于离线转发。
document = report_enhancements(document)
Path('/absolute/path/report.html').write_text(document, encoding='utf-8')
```

## 校验与交付

通过生成的最终 HTML 验证，不以临时组件页代替成品：

- 内容：成果覆盖完整，原型/截图/示意图区分清楚，主页面没有隐藏重要限制。
- 素材：图片全部能加载，说明对应正确图片，图中关系和文字没有错误。
- 交互：点击和键盘打开图片、Escape 关闭、焦点返回；展开/收起详情；导航跳到正确位置。
- 排版：检查桌面与手机竖屏，长标题、长表格、长图无意外溢出；检查已有主题下文字对比。
- 打印：检查打印样式和详情展开恢复。不能只检查屏幕截图便声称打印已验证。
- 转发：默认交付图片已内嵌、不依赖本地图片路径或 CDN 的单文件 HTML，保持用户原来的文件名或链接。参考材料链接可保留，但说明其访问条件。

不要把完整工作文档栅格化成一张长图。HTML 负责可阅读、可修改的内容，图片承担解释和展示。
