# 配方：方案对比与决策建议

适用：几个方案怎么选、技术选型、要不要做、给负责人的建议。读者需要拍板，但不需要逐题作答；需要逐题作答并回传选择时用 `decision-board`。

读者想知道：建议是什么、为什么、放弃了什么、代价和风险、拍板后下一步做什么。

## 结构

| 节 | 用什么表达 |
|---|---|
| 结论 | 页头定位 + `.verdict`：一句建议 + 一句理由。只看这里就能做决定 |
| 背景与问题 | 两三段：现在的问题、为什么现在要决定、不决定会怎样 |
| 候选方案 | `.options` 方案卡片，推荐项加 `.rec` 和 `c-ok` 标签；每张卡片写一句方案说明和 2-4 条要点 |
| 对比 | 表格「维度 / 方案 A / 方案 B / …」：收益、成本、风险、可逆性、时间；必要时配一张各方案的结构图 |
| 推荐理由与代价 | 为什么选它；放弃了什么；在什么条件下应该改选其他方案（写成可观察的触发条件） |
| 风险与应对 | 表格「风险 / 影响 / 应对」 |
| 下一步 | 拍板后的第一批动作、负责人、完成标志；需要谁确认什么 |

## 要点

- 每个方案都要写清代价，推荐方案也不例外。
- 投入产出比：说明收益多久出现、投入有多大；没有可靠数据时标明假设，不编精确数字。
- 「现在做 / 缩小范围做 / 暂缓」三种判断都考虑过，再给出建议。
- 对比表的维度按读者关心的顺序排，通常是收益 → 成本 → 风险 → 可逆性。
