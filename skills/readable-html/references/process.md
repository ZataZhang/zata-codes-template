# 配方：流程说明

适用：某个角色一整套怎么操作、业务怎么流转、多人协作怎么分工、操作手册、新人上手指南。

读者想知道：一件事从开始到结束分几步、每一步谁在做什么、东西落在哪里、多人怎么配合、出了问题怎么办。

## 结构

| 节 | 用什么表达 |
|---|---|
| 场景与角色 | 一段话交代例子（具体到业务对象，例如「上海到洛杉矶 40HQ 询价」）+ 角色表「角色 / 负责什么」 |
| 全流程泳道图 | `swimlane`：横向 4-6 个阶段，纵向依次是主角 → 协作角色 → 自动化 / Agent → 工作资料 → 正式资产 → 外部系统；主角泳道 `flow=True`，沉淀点用 `highlight` |
| 每一步做了什么 | `ol.steps` 编号列表，每步一段：谁触发、做什么、产出什么、注意什么 |
| 协作与流转 | 资料从个人 → 共享区 → 正式资产的流转图 + 「资料 / 各角色能看到什么」矩阵表 |
| 异常与边界 | 表格「情况 / 怎么处理 / 谁负责」，或 `.note` 写关键约束（例如「客户接受报价不等于舱位已确认」） |
| 衡量指标 | `.metrics` 3-4 张卡片，写可以实际统计的数 |
| 扩展到其他场景 | 「场景 / 新增什么 / 复用什么」表 |

## 要点

- 泳道图下方加一行阅读提示，说明每一列怎么从上往下读。
- 泳道单元格只写动作和极短说明；完整解释写进「每一步做了什么」。
- 不参与的阶段写 `"—"`，渲染成虚线占位，不要硬编一个动作。
- 用真实业务术语和单位（箱型、港口代码、SLA 时长等），不用「步骤 A」这类占位词。
- 权限矩阵里「不可见」要明确写出来，不要留空。
