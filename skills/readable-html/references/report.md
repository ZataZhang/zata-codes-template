# 配方：复盘与汇报

适用：事故复盘、项目复盘、周报 / 月报 / 阶段汇报、调研结论。

读者想知道：结果怎样、发生了什么、为什么、学到什么、接下来做什么。

## 结构

| 节 | 用什么表达 |
|---|---|
| 结论 | 页头定位 + `.verdict`：一句结果 + 一句最重要的判断 |
| 关键数字 | `.metrics`：影响范围、时长、完成度、核心指标的前后对比；每个数字写清口径和来源 |
| 经过 | `timeline`：3-7 个节点，异常节点用 `biz`，处置节点用 `gatelite`，恢复或完成用 `kn` |
| 原因 / 发现 | 复盘写根因链（现象 → 直接原因 → 根因），可用 `box` + `arrow` 画因果图；调研写发现，每条带证据 |
| 做得好的与要改进的 | 两栏 `.two` 或表格，一条一句话，配具体例子 |
| 行动项 | 表格「行动 / 负责人 / 截止时间 / 完成标志」 |
| 附录 | 原始数据、日志摘录、参考链接 |

## 要点

- 复盘对事不对人，写机制和条件，不写「某人没注意」。
- 汇报只放变化和需要读者知道的内容；没有进展的事项一行带过。
- 数字要能复查：写口径、时间范围和数据来源；估算值明确标为估算。
- 调研结论区分「已证实」「有迹象」「推测」，不把推测写成结论。
